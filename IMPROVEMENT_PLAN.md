# Focus-list — Improvement Plan

A weekend-by-weekend plan to turn this from a generated starter into a project that
shows **your** skill. Do it in order. Each item says *what to do*, *why it matters*,
and *what you'll learn*. Check boxes as you go.

> Rule for every change below: make it on a branch, write one sentence in the commit
> message explaining **why**, and be able to explain the change out loud. That last
> part is what makes this yours.

---

## Phase 0 — Get it running (do this first, ~30 min)

Nothing else works until you can run the app and its tests on your machine.

- [ ] Install **Node.js 22+** from https://nodejs.org (the "LTS" button).
- [ ] In the project folder, run:
  ```bash
  npm install
  ```
  ```bash
  npm run dev
  ```
  Open the URL it prints (http://localhost:3000). The app should load.
- [ ] Run the tests:
  ```bash
  npm test
  ```
- [ ] Run the type check:
  ```bash
  npm run lint
  ```

**You'll learn:** how a real project is installed, run, and tested — the daily loop
of every developer.

  that aren't part of the app.

## Phase 2 — Fix real bugs, one at a time (Weekends 2–4)

These are genuine bugs I found by reading the code. Fix **one per sitting**, add a
test for it, and write a one-line commit explaining the cause. Ordered easiest first.

- [ ] **Bug 1 — Undo button never appears.**
  In `src/hooks/useUndoRedo.ts` (~line 64) the return value is cached with `useMemo`,
  but `canUndo` / `canRedo` are read once and never update, so the on-screen Undo
  button stays hidden (Ctrl+Z still works). Fix: make `canUndo`/`canRedo` track the
  revision counter so the memo recomputes.
  *Concept: React `useMemo` dependency arrays.*

- [ ] **Bug 2 — Pomodoro count lost on import.**
  `src/utils/todoLogic.ts`: the JSON import (~line 701) doesn't copy
  `completedPomodoros`, and the CSV export (~line 539) leaves the column out, even
  though the README says it's included. Fix: carry the field through both.
  *Concept: data round-tripping / serialization.*

- [ ] **Bug 3 — Reorder arrows misbehave in filtered views.**
  `moveTodoOrder` (~line 213) swaps a task with its neighbour in the **full** list,
  which may be hidden by the current filter, so the visible order jumps oddly. Fix:
  reorder relative to the currently visible list.
  *Concept: keeping UI state and data state consistent.*

- [ ] **Bug 4 — "Task done" sound plays twice in development.**
  `src/App.tsx` (~line 332) plays the sound inside a state-updater function, which
  React StrictMode runs twice in dev. Fix: play the sound in an event handler, not
  inside `setTodos`.
  *Concept: pure updater functions and side effects in React.*

- [ ] **Bug 5 — Timer stuck at 00:00 after reload.**
  `src/hooks/useFocusTimer.ts` (~line 36): if a session ends while the tab is closed,
  it restores 0 seconds instead of rolling over to the break. Fix: when the restored
  time is 0, advance to the next mode.
  *Concept: time math and persisted state edge cases.*

For each: after fixing, add a test in the matching `*.test.ts` file and run `npm test`.

## Phase 3 — Ship it and make it real (Weekend 5)

A project nobody can try doesn't count. Deploy it.

- [ ] **Deploy to Vercel** (free): sign in at vercel.com with GitHub, "Import"
  Focus-list, accept the defaults (Vite is auto-detected), deploy.
- [ ] **Add the live link** to the repo: GitHub → repo → ⚙️ (top right) → "Website",
  paste the Vercel URL. Also add it to the top of the README.
- [ ] **Add one screenshot or GIF** of the app to the README so it's visible without
  running anything.

**You'll learn:** deployment, the thing most beginners never do — and the thing that
makes a repo feel finished.

## Phase 4 — Add one feature that's truly yours (Weekend 6+)

Pick **one** and build it yourself (ask me to guide, not to write it). This is the
part you'll talk about in interviews.

- [ ] **Dark mode** — a theme toggle saved to localStorage.
- [ ] **Recurring tasks** — "repeat daily/weekly."
- [ ] **A simple stats page** — tasks completed per day this week, as a small chart.
- [ ] **Keyboard-only task creation** — type `Tab: title @Work !high` and parse it.

Whichever you pick: design it first in a few sentences, then build it in small commits.

## How to know you're improving

You're ready to call this project a portfolio piece when you can, without notes:
1. Run it and the tests from a clean clone.
2. Explain what each file in `src/utils/` does and why the logic is split out.
3. Walk through one bug you fixed: the symptom, the cause, and your fix.
4. Show the live deployed link.

That's the real goal — not a longer repo, but one you fully understand.
